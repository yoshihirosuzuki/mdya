# collection と collection タイプ

mdya の文書は、どれも、どれかの collection に入っています。collection を作るときに、collection タイプを 1 つ選びます。collection タイプは、あとから変えられません。変えたいときは、collection を削除して作り直します。

| collection タイプ | `--type` の値 | 取り込み元 | 文書を変えるには |
|---|---|---|---|
| ディレクトリ | `directory` (既定) | ディレクトリ | ディレクトリの中のファイルを変えて、`mdya update` |
| アーカイブ | `archive` | zip、tar、gzip で圧縮した tar のファイル | アーカイブを作り直して、`mdya update` |
| raw | `raw` | 利用者が `mdya put` で渡す文書の内容 | `mdya put` で渡し直す |

## collection が持つもの

- collection 名: collection を区別する名前です。ASCII の英数字と `-`、`_` だけからなる、1〜64 文字の名前です。大文字と小文字は区別します。同じ名前の collection は作れません。
- collection タイプ: 上の表の 3 つのどれかです。
- タイプ別の属性: ディレクトリとアーカイブの collection では、取り込む場所です。raw の collection にはありません。
- 説明: collection の意味を、名前のほかに表す文です。省略できます。AI アシスタントは、MCP の `list_collections` で説明を読み、どの collection を探すかを決めるのに使えます。

## 場所の渡し方

ディレクトリとアーカイブの collection に場所を渡すときは、次のとおりに読みます。

- 先頭の `~` は、ホームディレクトリに置き換えます。
- 相対パスは、そのコマンドを流したときの作業ディレクトリから解決します。mdya は、場所を絶対パスとして持ちます。そのため、どの作業ディレクトリで取り込んでも、同じ場所を取り込みます。
- 絶対パスにするときは、`.` だけの階層を取り除きます。`..` の階層は残します。シンボリックリンクはたどりません。

## ディレクトリ

ディレクトリの中のファイルを、文書にします。

- 文書にするもの: ディレクトリの中の、拡張子が `md`、`markdown` (Markdown) か `pdf` (PDF) のファイルです。拡張子の大文字と小文字は区別しません。ほかの拡張子のファイルと、拡張子のないファイルは、文書にしません。名前が `.` で始まるファイルやディレクトリも、ほかと同じく扱います。
- key: ファイルの、ディレクトリからの相対パスです。区切りの文字は、どの OS でも `/` です。
- 文書のバージョン: ファイルの最終更新時刻と、文書の本文で区別します。
- update: その collection の文書を、ディレクトリの今の中身と一致させます。新しいファイルを足し、変わったファイルを取り込み直し、なくなったファイルの文書を削除します。ただし、読めない文書と、ディレクトリを読んでいる途中で読めなかったところの文書は、前の文書のバージョンのまま残します ([エラーと直し方の「読めない文書がある」](errors.md#読めない文書がある)、[「取り込み元を読めない」](errors.md#取り込み元を読めない))。

### シンボリックリンク

ディレクトリの中のシンボリックリンクは、たどりません。リンクそのものも文書にしません。取り込むディレクトリの場所そのものがシンボリックリンクなら、リンク先のディレクトリを取り込みます。

リンク先の場所を取り込みたいときは、その場所を、別の collection にしてください。

### `.gitignore`

取り込むディレクトリが git のリポジトリの中にあるときは、`.gitignore` の規則で除かれるファイルを、文書にしません。リポジトリの中にあるとは、そのディレクトリか上の階層に、`.git` (ディレクトリかファイル) か `.jj` ディレクトリがあることです。

- 上の階層の `.gitignore` の規則も、中のファイルに掛かります。取り込むディレクトリそのものには掛かりません。
- `.git/info/exclude`、利用者全体の除外の設定、`.ignore` は読みません。

`.gitignore` で除いているファイルを、mdya には取り込みたいときは、その規則を `.gitignore` から `.git/info/exclude` に移してください。git はどちらの規則でもファイルを除き、mdya は `.git/info/exclude` を読みません。

### 文書にしないもの

- 通常のファイルでないもの (デバイス、名前付きパイプなど)。
- 相対パスを UTF-8 として読めないファイル (Windows では、対になっていないサロゲートがあって、Unicode の文字として読めないもの) は、読めない文書として数えます ([エラーと直し方の「読めない文書がある」](errors.md#読めない文書がある))。

## アーカイブ

アーカイブのファイルの中の項目を、文書にします。mdya は、アーカイブをディスクに展開せずに読みます。

### 扱うアーカイブ

| 形式 | 拡張子 |
|---|---|
| zip | `.zip` |
| tar | `.tar` |
| gzip で圧縮した tar | `.tar.gz`、`.tgz` |

形式は、アーカイブの場所の拡張子で、大文字と小文字を区別せずに見分けます。bzip2・xz・zstd で圧縮した tar、7z、rar など、ほかの形式は扱いません。

アーカイブの場所そのものがシンボリックリンクなら、リンク先のアーカイブを取り込みます。

### 文書にするもの

アーカイブの中の項目のうち、拡張子が `md`、`markdown` か `pdf` のものを文書にします (ディレクトリと同じ決まりです)。次のものは、文書にしません。

- 通常のファイルでない項目 (ディレクトリ、シンボリックリンク、ハードリンク、デバイスなど)。リンクの項目は文書になりませんが、リンク先がアーカイブの中の、文書になる項目なら、その内容は、リンク先の名前の文書として検索できます。
- macOS が足す付加情報の項目。最上位が `__MACOSX/` の項目と、最後の階層の名前が `._` で始まる項目です。
- アーカイブの中のアーカイブ (中の `.zip` など)。開かず、文書にもしません。中の文書が検索に出てこないときは、アーカイブの中にアーカイブがないかを確かめてください。

アーカイブの中の `.gitignore` は使いません。

tar の中のスパースファイル (データが全部ゼロの部分を省いて格納したファイル) は、通常のファイルと同じ条件で文書にします。省いた部分をゼロで埋めた、元のファイルのとおりに読みます。

tar は、tar の終わりを示す、全部ゼロのブロック 2 つの後ろを読みません。そのため、いくつかの tar をつないだファイルでは、2 つめの tar からの項目は文書になりません。

### key

アーカイブの中の名前を、最上位のディレクトリも含めてそのまま使います。

- 名前の中の `\` は区切りとみなして `/` に置き換えます。
- `.` だけの階層と空の階層は取り除きます (`./docs//a.md` は `docs/a.md`)。
- `..` の階層と制御文字は、そのまま key に入れます。mdya は、中の項目をディスクに書き出さないためです。
- 同じ key になる項目が複数あれば、アーカイブの中で後にある項目を使います。zip では、zip の末尾にある項目の一覧 (central directory) の中の順で後先を決めます。
- 名前は UTF-8 として読みます。zip で、名前が UTF-8 であることを示す印 (general purpose bit flag の bit 11) のない項目も同じです。ただし、その印のない項目に、名前を UTF-8 で入れた追加の記録 (Info-ZIP Unicode Path Extra Field) があり、その記録のバージョンが 1 で、記録に入っている CRC32 が、zip の末尾の一覧の中の、その項目の名前と合うときは、その記録の名前を使います。

### 文書のバージョン

アーカイブ自体の最終更新時刻と、文書の本文で区別します。中のどの文書も、アーカイブの最終更新時刻を使います。

### 読めない文書になる項目

文書になる項目のうち、次のものは、読めない文書として数えます ([エラーと直し方の「読めない文書がある」](errors.md#読めない文書がある))。前に取り込んだ文書のバージョンがあれば、そのまま残します。

- 展開したあとの大きさが 256 MiB (1 MiB は 1,048,576 バイト) を超える項目。超えたところで読むのをやめます。
- zip で、無圧縮と deflate のほかの方式で圧縮した項目と、暗号化した項目。
- 名前を UTF-8 として読めない項目。key がないので、前の文書のバージョンもありません。

### アーカイブ全体を読めないとき

次のアーカイブは、全体を読めないものとして扱います。その collection の文書は、update の前のまま残ります ([エラーと直し方の「取り込み元を読めない」](errors.md#取り込み元を読めない))。

壊れているもの:

- 途中で切れているもの。たとえば、ダウンロードやコピーが途中で止まったファイル。
- zip で、項目の一覧 (central directory) やその中の記録が壊れているもの。
- zip で、いくつかの項目の圧縮データが重なっているもの。小さな zip に、展開すると大きくなる項目をいくらでも入れられるためです。
- tar で、項目のヘッダーのチェックサムが合わないものや、pax の拡張ヘッダーの記録の形が崩れているもの。
- gzip で圧縮した tar で、tar の終わり (全部ゼロのブロック 2 つ) を含む部分までに、展開したデータの検査の値 (CRC32) が合わないところがあるもの。tar の終わりを含む gzip の部分 (member) の後ろは読まないので、そこは確かめません。

壊れてはいないが、読めない形のもの:

- tar (gzip で圧縮した tar を含む) の末尾に、tar の終わりを示す、全部ゼロのブロック 2 つがないもの。項目の境目でちょうど切れたものと見分けられず、読めたことにすると、切れた先の文書を削除してしまうためです。この終わりを書かない作り方の tar は、中の項目が正しくても読めません。
- 複数のファイルに分割された zip。
- ファイルの先頭に別のデータ (自己解凍のプログラムなど) を付け、zip の中の位置を直していない zip。

そのほか:

- アーカイブのファイルがないか、読む権限がないもの。
- 中の一覧の大きさが上限を超えるもの。文書になる項目 (読めない項目を含む) ごとに、名前のバイト数に 128 バイトを足して数え、その合計が 256 MiB を超えるときです。同じ key になる項目も、1 つずつ数えます。文書にしない項目は数えません。ただし、名前を読んでいる途中の項目は、文書になるかが決まるまで、読んだ名前のバイト数も合計に入れて比べます。そのため、とても長い名前の項目では、文書にしない項目でも、文書になるかが決まる前に上限を超えることがあります。
- 中の一覧を読んでいる間に、アーカイブの最終更新時刻か大きさが変わったもの。書き換えの途中の崩れた一覧で、文書を削除しないためです。

### 大きさとメモリ

- 1 つの項目の展開したあとの大きさの上限 (256 MiB) と、中の一覧の大きさの上限 (256 MiB) は、設定で変えられません。
- アーカイブの中の文書の大きさの合計には、上限がありません。圧縮やスパースファイルのため、小さなアーカイブから、256 MiB までの文書がいくつも出てくることがあります。作り手のわからないアーカイブを取り込むときは、そのぶん取り込みに時間がかかり、インデックスが大きくなることを見込んでください。
- アーカイブの中の文書は、取り込むときに 1 つずつ読みます。先に読んで溜めることはしません。同時に処理する文書の数は並列の度合いで決まるので、mdya が使うメモリは、並列の度合いを上げるほど増えます ([設定の「メモリと並列の度合い」](configuration.md#メモリと並列の度合い))。

## raw

利用者が `mdya put` で渡した文書の内容を、文書にします。

- 取り込み元: `mdya put` で渡したファイルか、標準入力です。
- key とファイルタイプ: `mdya put` で渡します。
- 文書のバージョン: 文書の本文だけで区別します。文書の本文が前と同じなら、`--force` を付けない限り、取り込み直しません。
- update: できません。取り込み元の最新の情報を探す手段がないためです。
- 文書がインデックスからなくなるのは、collection を削除したときと、`mdya remove` で文書を削除したときだけです。

raw の collection の文書は、update で取り込み直せません。削除したあとに戻すには、同じ文書の内容を、もう一度 `mdya put` で渡す必要があります。文書の内容を残しておいてください。
